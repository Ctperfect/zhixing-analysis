# 知行问题分析的配对评测

评测日期为 2026-11-08。评审所用的提交 `e8e56e2c0264c0189fc1c046442db0ebea92de2b` 在拉取时仍是远端 `main`。本次评测比较本改动的 Skill 与无 Skill 的对话。原评审提交用于确认改动起点。

## 设计

每次全量比较包含 [20 个合成情境](cases.json) 的两组结果，共 40 个独立会话和 54 个用户回合。四组情境包含多轮回放，覆盖确认保存、查看修改删除、中断重启和容量变化。两组都使用 `gpt-6.1-sol`、`low` 推理档、相同用户文字、种子文件与工具权限。有 Skill 组只启用待评版本，并使用 Codex 原生技能附件。无 Skill 组的可用技能列表为空。每个情境从独立目录开始。

文件检查比较每轮前后的实际文件，验证允许的创建、更新、删除与省略字段。另检查两份未经授权的合成旧记录是否出现在读取结果或回复中。报告的文件结果依据实际差异。涉及聊天内容、状态和简洁程度的判断由两位独立助手分别评估十组。对每题随机分配 A/B，去掉回复中的测试目录前缀和明确的技能名称。评审按预先写好的两项行为标准检查，整体差异对用户无实质影响时判平。

试跑中的查看与删除题同时出现了 `private` 和 `../private`，使模型可能找错目录。统一路径后，双组都在最终输入上重跑。首轮盲评发现两次未执行与效果验证没有说清楚，纸笔验证也欠缺同口径比较。随后补足这两条指令，重跑 20 个有 Skill 会话。无 Skill 组沿用已完成的同配置结果。第二次全量盲评又发现一个共享仓场景的提示缺口，随后只改记录规则，并复验七个相关情境。

## 宿主与复现

实测宿主为 Windows 上的 `codex-cli 0.167.0-alpha.3.2`，覆盖 App Server 技能附件和 `codex exec` 中的显式 `$zhixing-analysis` 调用。命令行的加载事件确认读取了 `.agents/skills/zhixing-analysis/SKILL.md`，随后完成一句概念解释。宿主验证以这个版本和这两条路径为范围。桌面界面和其他 AI 工具各需单独验证。

使用已登录的 Codex、Python 3.12 和 Git，执行下列命令。

```powershell
python -X utf8 evals/run.py --model gpt-6.1-sol --jobs 4 --out .local/evals-final
python -X utf8 evals/verify.py --out .local/evals-final --blind
```

运行器在指定目录保存回复、工具事件和每轮文件变化。同一输入、运行器、宿主和待评技能内容相同时可复用已完成结果。用 `--out .local/evals-next` 可创建独立复验。核验器检查实际回合、两组输入和配置、技能附件、文件变化与受保护标记。有 Skill 组出现文件或受保护读取检查失败时，核验器返回失败。[公开结果汇总](RESULTS.json)保留指标与判定依据，原始运行路径和工具日志留在本机。

## 结果范围与真人试用

每轮完整比较在 20 个合成情境中各取一次样本。两组分别跑固定回合，回访语句不会随模型回复变化。每题由一位助手评审，答复风格可能透露条件。修订参考了同一题集，组间偏好也受生成波动和评分员判断影响。证据范围是这些对话和文件行为，现实行为变化需要真人试用。

真人试用可由少量自愿使用者带入一个真实目标，用同一个模型比较不同条件下是否愿意回来、是否完成一个自选动作、是否知道怎样暂停或重启，以及协作有多费力。由参与者选择是否留记录。评估只收集经确认的匿名结果，日记与私人细节留在参与者自己的范围内。
