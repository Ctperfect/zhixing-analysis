# 项目案例：工厂 ERP 怎样选第一条链路

以下是用于说明推理的假设情境，具体结论须由现场资料核实。

## 从功能清单回到业务目标

老板希望上线全模块，当前主要抱怨是交付延期。先明确要改善的结果、范围和约束，再讨论模块。销售、仓库、生产与财务的诉求可能不同，功能数量不能直接表示价值。

## 还原事实并建立替代解释

| 可能解释 | 需要观察的材料 | 会改变判断的情况 |
|---|---|---|
| 库存数据不准导致缺料 | 账实差异、缺料记录与延期订单的关联 | 库存已准确，延期仍然发生 |
| 产能或排程形成限制 | 工序负荷、排队时间、设备与人员安排 | 材料齐全但关键工序持续排队 |
| 承诺与需求变化失配 | 订单承诺、变更与交付记录 | 接单承诺已超出可用资源 |

第一性原理在这里检查“全模块一次上线是否为改善交付的必要条件”。机制解释需要连接具体卡点与延期结果，不能把所有问题归入信息差。

## 选择最小验证

如果证据指向库存准确性，可以选一种物料、一个班组或一条低影响流程，检查统一记录是否减少实际缺料。提前保存基线、观察窗口与其他变化，约定何种结果支持继续推广。

如果资料显示库存已准确，先检查排程或承诺的解释，再决定范围。所选小流程必须针对当前最重要的未知，而不只是开发方便。

涉及生产切换时，验证可以先在历史数据、模拟环境或受控试点中完成。一次试点要说明数据与生产影响、观察办法及可恢复范围；“最小”并不意味着把未经检查的系统直接投入关键业务。

## 推进、反馈与停止

如果用户需要跨阶段推进，先确认希望看到阶段、每周还是每日安排，以及本次细化多久。根据现场资源形成路线，例如：取得并检查历史资料 → 区分主要延期解释 → 设计受控试点 → 观察业务反馈 → 决定扩大、调整或停止。

资料访问是前置条件，试点方案依赖主要解释与影响范围得到澄清，推广依赖试点反馈。流程访谈、资料准备等可根据真实依赖并行。多人协作时明确相关负责人和交接条件，按实际容量排期。关键资料未获得时标记受阻，调整可先开展的工作；每日表只在用户选择相应粒度后展开。

每一步可以交付一份流程图、一次账实对照或一条经验证的链路。流程确实减少卡点后再扩大范围；若没有改善，检查执行、测量、机制解释和目标选择。

如果改善没有业务价值，或者原假设被反例推翻，缩小或停止相应模块是合理结果。这个案例保留“小步落地”，同时让选择小步的理由能够被检查。
