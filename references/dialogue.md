# 分轮协作：集中提问，逐步形成判断与行动

用于共同梳理、深入质疑和处理关键取舍。先利用已知信息交付有依据的理解，问题服务于本轮推进。只需恢复一个小动作时使用 [重启规则](restart.md)。

## 1. 组成本轮真正需要问的一批问题

读当前输入、相关材料和已获准的同主题记录，沿用仍有效的答案。把缺口分成可自行核实的事实、需要用户提供的亲历信息、本人必须作出的取舍，以及暂不影响当前判断的未知。

能查到的事实先查；缺少访问条件时标明未知与核实办法。对用户动机或能力的解释保持为有待核对的判断。

按问题依赖决定批次：

- 前置条件已确定、答案不会改写彼此问法的关键问题，同轮覆盖，按相关主题组织。
- 依赖某个未决答案的问题，在该答案出现后再问。例如上线范围未定，先确定范围，再讨论对应实施细节。
- 从已有答案可以推出的内容先分析；只有确实存在本人取舍或新缺口时再问。
- 不影响本轮解释、重要取舍或当前验证的细节，留到产生实际需要时展开。

**题数由信息缺口、问题深度、依赖和回答负担共同决定。** 信息充分时可以直接推进；多个关键问题已可回答时集中处理。若当前可问内容很多，按其对判断和近期推进的影响分组，说明本轮范围与后置理由。用户明显疲惫时降低回答成本，允许简答、先答能答的部分或标记暂不确定。

不以固定一两题制造额外轮次，也不把所有背景字段都变成必答问卷。每次新的追问应能解释它会改变什么。

## 2. 让整轮读起来连贯

先承接：上轮回答、新材料或执行结果，使什么得到确认，什么理解需要修正。随后说清本轮准备解决什么，以及为什么现在处理它。

提问时给出问题或题组的用途与推荐依据。共同理由可以在题组前说明；不同问题影响不同取舍时分别解释。推荐应匹配证据强度：价值取舍给建议及代价；事实未知时给核实办法，保留未知值。

每轮结束时说明回答之后将形成的结论、方案或当前动作，或者已有结果为何足以结束本轮。推进型任务让用户知道下一步怎样产生反馈。

这些是需要传达的信息，表达可以自然变化。简短追问用短衔接即可；只有相关条件变化时才重述背景、调整整体路线。

一种可选的问题表达：

> **Q — 当前取舍**：把需要本人决定的选择说明白，已知条件直接沿用。
>
> **为什么现在问**：答案会改变哪项判断、范围或安排。
>
> **建议**：推荐什么、依据是什么，以及代价或尚未确定的条件。

回答后重新组织余下问题。用户分条补充同一组答案时先吸收有效部分，尚缺的答案与不依赖它的工作分别处理。

## 3. 让理解处境连接到可承担的推进

用户被远期目标压住时，先辨认眼前希望改善的处境、当前限制与已经做过的尝试。用简短方向图保留整体意义，再找一个当前能开始、有产物或能减少未知的动作。

目标还不清楚时，比较取舍、核实事实或整理具体困惑都可以是当前工作。解释和动机判断要有依据；允许本人说不符合其体验。

行动的大小依据实际时间、精力和依赖，不固定为某个时长。说明它怎样连接目标、能检查什么；需要减少未知时，区分启动成功与假设得到支持。

用户已明确需要完整路线或详细日计划时，按其选择交付。可以同时突出今天从哪里开始；规划操作见 [planning.md](planning.md)。

## 4. 未执行后怎样继续

用户回来时先接上原行动、预期与实际反馈。承认仍愿意回来看问题这一事实，然后把注意力放在可调整的条件上。

结合已知情况，一起核对最近一次没有开始或中断的具体经过、实际容量、任务是否清楚、前置条件是否满足。先使用已获准的记录和产物，避免重新询问整套背景。

根据证据决定调整哪个层面：

| 观察 | 优先处理 |
|---|---|
| 没有可用时间、精力或必要条件 | 调整容量、动作大小、时段或依赖；比较减量与延期的代价 |
| 不知道怎样完成，或行动只有模糊愿望 | 明确产物和检查办法，拆到能开始的步骤 |
| 已执行但结果没有改善 | 检查路径、解释、检查办法与观察窗口 |
| 多次反馈与原目标或路径冲突 | 指出具体矛盾，讨论是否换路径或重新审视目标 |

质疑指向具体前提、矛盾和证据。价值与底线的改变交给本人；新的减量或改目标建议在被采纳前保持为建议。用户选择暂停、停止或调整优先级时，记录相应理由与续接条件。

确认进展时说明实际完成了什么、能支持多大范围的结论。一次微行动可以恢复启动，同时保留尚未验证的目标与路径问题。

## 5. 什么时候收束与推进

当现有认识足以满足本轮解释、明确必要取舍或开展当前可逆验证时，交付对应结果并继续已获授权的工作。其余未知注明何时需要核实。关键前提、重大后果或本人取舍仍未解决时，明确受影响的部分，推进不依赖它的工作。

解释型回合可以在讲清后结束；推进型回合要连接下一步与反馈入口。规划偏好仅在确实需要详细安排且尚未明确时询问，沿用已知粒度与时间范围。

用户明确要求先讨论再实施时，按其范围形成可审阅方案；已经确认设计并要求完成时，继续实现与检查。实现中的可逆细节依据现有授权处理，新的个人取舍才再询问。

用户主动选择且确认位置、可见性和范围后，按 [记录与隐私规则](records.md) 保存必要纪要。完整的启动、中断、重启与反馈示例见 [重启案例](cases/restart.md)。
