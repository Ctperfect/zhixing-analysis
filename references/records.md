# 专用目录中的多文件记录与续接

用于多轮讨论、多约束决策、项目推进与复盘。目标是同时保留过程依据和当前有效状态，让后续协作知道从哪里继续。

## 1. 保存位置与创建时机

复杂任务默认保存；简单解释按需保存。用户明确要求只聊、只保存最终总结或使用指定位置时，沿用其选择。

**所有协作记录归入专用目录，默认 `docs/zhixing/<能辨认主题的目录名>/`。** 先在当前工作区或用户指定位置查找同主题材料，避免重复建档。用户已指定另一专用目录时沿用；只给出项目根路径时，以它为基目录创建知行主题目录。

入口、轮次纪要、策略、计划、术语、必要决策记录和验证附件都放在该专用目录下面，工作区根目录不散放记录文件。技能参考目录用于通用说明，当前任务材料放在使用者的工作区中。

有实际内容时才创建相应文件。一个复杂主题可以先有入口和本轮纪要，策略成形后再建立策略文件，需要行动安排时再建立计划文件。创建数量与内容需要一致，避免空文件和无用字段。

## 2. 每类文件的职责

```text
docs/zhixing/<主题>/
├── README.md
├── strategy.md
├── plan.md
└── rounds/
    ├── 001.md
    └── 002.md
```

用户已有命名惯例时可以沿用，职责保持清楚：

| 文件 | 主要维护内容 | 更新条件 |
|---|---|---|
| 入口 `README.md` | 主题、当前所在环节、相关材料入口、有效结论与下一步的短导航 | 建档或当前进展改变 |
| 当前策略 `strategy.md` | 希望改善什么、目标与约束、事实和解释、路径与取舍、关键未知、何时改变判断 | 理解、证据、约束或取舍改变 |
| 当前计划 `plan.md` | 选定粒度与时间范围、阶段与近期行动、资源和依赖、产物与检查、状态和证据、反馈点 | 需要行动安排，或执行反馈与条件改变 |
| 轮次 `rounds/NNN.md` | 本轮输入要点与必要原话、分析依据、提问及理由、用户回答与确认、未决事项、造成的改变 | 每轮实质讨论保存和补充 |

**轮次保留历史，策略与计划各维护一个当前有效版本。** 同一事实、约束或取舍有一个主要描述位置，其他文件简短引用；入口帮助定位，不复制整套计划。需要独立比较旧方案时，再保存相关快照及其来源。

重要术语可以在主题目录中增加 `glossary.md`；只有确有长期取舍成本、需要单独说明来龙去脉的决定才使用该目录下的 `decisions/`。普通方案变化在轮次纪要中记录即可。

## 3. 一轮怎样记录

一轮是围绕一批当前问题形成实质理解或推进的一次协作。用户对同组问题分条作答、补充一句或确认，通常归入同一轮；新的分析、取舍或反馈再形成后续轮次。

发问时先记录本轮已有分析、问题与理由，标为待答；答案到来后补充其实际内容与影响。下一轮开始前吸收已得到的答案，保留尚未回答的部分。

默认保存结构化纪要和必要原话。逐字稿仅在用户明确需要、且完整内容确实可取得时提供。不能把整理后的摘要称为完整原始对话。

可按实际内容使用以下结构：

```markdown
# 第 N 轮：本轮主题

日期与状态：待答、已答或本轮完成。

## 本轮输入与已有信息
输入要点、必要原话、材料来源；沿用的条件链接原记录。

## 理解与依据
能确定什么、解释与假设、仍缺什么；本轮为什么处理这些问题。

## 问题、理由与回答
各问题或题组的作用、推荐及依据、用户实际回答。

## 确认、建议与未决事项
分别写明状态，说明答案改变了什么。

## 本轮结果与下一步
已形成的理解、取舍或安排；当前文档的更新位置与随后怎样继续。
```

轮次记录保留当时的状态。后续发现错误时补充更正及来源，让读者能看见为什么改变判断；当前有效结论同步到对应策略或计划。

## 4. 当前策略与计划怎样保持有效

策略围绕“为什么这样处理”组织：当前问题与结果标准、重要约束、证据与解释、所选路径、已确认取舍、尚待验证的判断及调整条件。依据强度与采纳状态清楚可见。

计划围绕“接下来怎样做、怎样检查”组织。长期项目保留整体路线与关键依赖，按用户选择细化阶段、每周或每日安排。当前行动说明产物、资源、前置条件和反馈入口；具体安排见 [planning.md](planning.md)。

状态应能够区分：

- **本人已确认**的目标、取舍与承诺；
- **助手建议**及其尚未采纳或已采纳状态；
- **待核实解释**、假设与估算；
- **未开始、进行中、受阻、已完成、待验证**等实际进展。

任务完成指向实际产物或注明来源的用户报告。用户自述、已读取的材料与实际运行结果分别记录。行动完成、验证通过与项目目标达成各自依据对应证据。

用户回来反馈时，对照原预期、实际观察和解释更新。只更新受影响的目标、路径、任务、日期或依赖，保留仍有效的安排。未被采纳的缩减或改目标建议维持条件化状态。

“当前计划已形成”可以完成一次规划回合；项目还处于执行或验证中时，入口与计划保留相应状态。停止或暂停时记录本人决定、理由，以及是否存在恢复条件。

## 5. 续接与旧记录整理

续接先读取入口，再读当前策略和计划；依据未决事项、引用和最近变化追溯相关轮次。以当前实际文件和最新输入为依据，避免把历史建议当作已经确认的决定。

用户只问局部概念时，利用已有上下文就该问题作答；有新证据影响计划时才更新对应部分。

已有单个主题文件时，先读其当前有效内容与历史。将当前摘要、策略和计划按需要分入主题目录，原件可作为该目录下的历史材料保留并链接。迁移前核对内容、目标位置与现有引用，迁移后更新入口和有关链接；旧文件承担的追溯作用要有实际替代位置。

用户已指定单文件时，遵从指定形式，在专用目录内通过章节保留必要职责。

## 6. 保存后核验与工具限制

保存后回读相关文件，检查本轮纪要、现行结论和计划是否一致，内部链接能否定位，确认与建议是否混淆，实际写入位置是否在专用目录。回复给出已保存文件的实际链接；文件数量本身不表示工作推进。

无法写入时交付可复制的精简记录，并明确尚未保存；能读取的既有材料继续利用。以实际能力说明怎样续接，不把文件记录描述为自动提醒或永久记忆。
