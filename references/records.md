# 记录、隐私与续接

默认在对话内工作。用户可以用一句“原来准备做什么、发生了什么、现在想怎样继续”续接。只有主动选择文件记录的用户才需要考虑以下操作。

## 首次保存的三项确认

1. **位置**。说明将写入的文件或目录。用户明确选择私人位置时，用用户确认的实际路径。项目记录可用获准项目中的 `docs/zhixing/<主题>.md` 或已有主题目录。
2. **可见性**。根据已有信息说明谁可能访问该位置。Git、公司项目、共享盘或云同步目录可能由成员、管理员、同步或提交的接收者看到。未知时说明未知，由用户确认访问与同步情况。
3. **范围**。告诉用户将保留哪些必要信息，例如当前目标、下一步和反馈，明确省略的敏感细节。等用户确认位置、可见性和范围后，再实际写入。若用户已经明确确认这三项，简短复述后可以执行。

“帮我留个记录”、已有文件、工作区位置、`.gitignore` 或助手建议的路径都不足以确认这三项。私人话题优先请用户选择自己控制的位置，保持在公司、共享、Git 或同步目录之外。访问情况不明时留在聊天内，按用户需要给可复制摘要。对话摘要同样只保留当前需要的信息。

用户在公司或共享工作区请求留档时，即使当前选择在对话中提供摘要，也用一句话说明该工作区的潜在可见对象。例如同事或仓库协作者可能通过共享、同步或提交看到文件。随后请用户指定或确认自己控制的位置、实际访问范围和拟保存内容。只聊而未提出保存时无需这段说明。

用户说“只聊”“别读旧记录”或“别写文件”时，按各自范围执行。简单解释、倾诉或眼前动作通常用对话即可。进入讨论时无需为了留档主动展开保存流程。

## 范围与数据最少化

- 写入前核对实际解析的路径及其归属。目标若越过已确认目录，或者可见性、主题或保存范围改变，回到对应的确认。保存许可不包含提交、同步、外发或向其他人共享。
- 优先保存影响后续行动的摘要。姓名、联系方式、具体健康、家庭或财务细节、客户数据和逐字原话通常省略，能用资源或状态描述时使用抽象表述。明确请求且确有必要的原文或敏感内容，也只在获准的范围内处理。
- 已有同主题且同位置、同可见性、同范围的确认可沿用。旧版自动落盘的记录不构成确认。查看或续接按用户指定文件或先前授权范围读取，避免遍历无关目录或私人主题。
- 项目参与者可见的记录限于用户明确确认可共享的信息。信息来源是本人陈述、材料、实际验证还是推断，要足以从记录判断。建议在采纳前标明为建议。

## 记录足够续接即可

首次可用一份短记录，包含当前目标、约束与下一步，已确认决定和待核实判断，实际反馈及更新。文件有实际内容才创建。每轮只更新变化和仍有效的结论，避免重复记录整段对话。

复杂主题已有 `README.md`、`strategy.md`、`plan.md`、`rounds/` 时沿用。入口定位当前判断和行动，策略与计划维护现行版本，必要的轮次只存变更和依据。旧单文件继续按原形更新。需要迁移时先说明源、目的地、可见性和范围，经明确授权后处理。移动前核对引用与原件。

行动状态对应证据。用户自述要注明来源，能查到的产物可复核，完成任务和验证假设分别记。停止或暂停记录本人选择及恢复条件。用实际反馈更新受影响的部分，已采纳与未采纳分开。

## 查看、修改、删除

- **查看**。用户给出文件或获准目录后，仅定位该主题，说明实际位置和可见性。只读请求保持文件不变。
- **修改**。更新用户指定的内容并回读校对。删除某项敏感细节时，也检查是否在本次明确授权的同主题材料中有需要处理的副本，范围以本次请求为准。
- **删除**。用户已明确指定记录和删除范围时，核对解析路径，只删除该范围内的文件，再核实并报告实际结果。范围不明时列出可操作对象，由用户指定。同步、副本和 Git 历史需要分别确认处理范围。

工具受限时说明实际状态，给可复制摘要或具体操作入口。只有确认写入或删除确实完成，才报告完成。继续讨论始终可以在当前对话内完成。
