# 复杂任务的文件记录与续接

## 何时保存

多轮讨论、多约束的决策、项目推进和复盘默认保存。简单解释按需保存。用户明确要求只聊、使用指定文件或只保存最终总结时，依照本次要求执行。

记录保存在当前项目或指定目录。先查找同主题文件并阅读；沿用现有组织。没有现成结构时创建 `docs/zhixing/<能辨认主题的文件名>.md`。实际写入前检查目标位置与现有内容，避免另起重复记录。技能参考目录用于通用说明，不存放当前任务的个人档案。

## 建议记录内容

先写当前摘要，让续接者能快速辨认当前任务、有效约束、结论状态和下一步。详细事实各保留一处，后文引用其影响；每轮更新当前状态并追加有意义的变化，避免反复复制整段分析。

长期项目的记录还承担当前工作状态的续接。按需保留用户选择的规划粒度与细化范围、整体路线、阶段检查点、当前任务的状态与证据、阻塞及资源变化。字段随实际任务裁剪，已有详细计划用链接引用。

个人或小型项目优先使用一个当前摘要和一份现行计划或状态表；只有新增内容需要独立解释时再增设小节。同一事实、约束或未决取舍保留一个主要描述位置，其他地方简短引用。变更记录只写条件如何变化及原因，原对话已有完整旧计划时用链接定位。

下面是可按需裁剪的模板。只保留实际有内容的部分；复杂主题可以展开证据，小问题沿用已有简短记录即可：

```markdown
# 主题

## 当前摘要

当前需要、有效目标与约束、结论及其状态、接下来做什么或为何结束。这里只放当前有效状态。

## 事实与依据

必要事实、材料或自述的来源、重要未知。验证发生时记录原预期、实际观察及认识更新。

## 决定、建议与未决事项

分别标记本人已确认的取舍、助手建议及采纳状态、需要核实的解释和问题。需要推进时写下一步产物与检查办法，已有详细方案时引用它。

## 当前计划与进展（需要时保留）

粒度与细化范围、可用资源、整体阶段及检查点；近期任务、估算、依赖、当前状态与实际证据。详细计划单独存在时引用它。标记暂定安排、已确认决定及尚待核实条件。

## 变更记录

只记录影响理解或方案的变化，例如投入时间改变、假设被推翻或本人改了优先级。
```

## 更新规则

- 写清“本人已确认”“助手建议”“待核实解释”三种状态。只有本人明确采纳后，才把建议转成已确认决定。
- 使用可获得的当前日期或会话轮次标记变化。旧记录与新输入不一致时，把新条件写入当前部分，并保留旧条件及变化依据；不让旧计划覆盖本人最新决定。
- 复盘时并列记录原预期、实际证据和更新后的判断。素材不足时记录限制，避免制造精确指标或虚构结果。
- 任务“已完成”需对应实际产物或用户报告的来源；建议的日程不表示已经执行。受阻、待验证和完成分别记录。资源或目标改变后，同步更新受影响的阶段与近期安排，清楚标记尚未解决的冲突。
- 已记录且仍有效的规划偏好和事实直接使用。局部答疑只在产生相关新证据时更新对应内容，保持当前摘要可读。
- 命名与术语形成重要共识时，可更新已有项目术语表。架构决策记录只用于确有长期取舍成本的设计选择，普通讨论使用主题记录即可。
- 保存后检查文件实际存在、内容与本轮结论一致，并在回复中链接。下一轮用文件定位和读取结果继续讨论，不声称具有文件以外的永久记忆。

## 工具受限时

能读文件时先利用已有记录；无法写入时，在回复中交付可复制的记录，明确尚未保存。用户当前指定的只读要求优先于默认保存；不用修改权限或写到无关目录来绕过限制。
